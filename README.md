# Bookroom 📚

[![CI](https://github.com/alinasavuyk/bookroom/actions/workflows/ci.yml/badge.svg)](https://github.com/alinasavuyk/bookroom/actions/workflows/ci.yml)

Книжкова соцмережа-маркетплейс: діліться враженнями про прочитане, ведіть особисту бібліотеку, продавайте чи обмінюйте книги з іншими читачами.

**🔗 Живе демо: [bookroom-phi.vercel.app](https://bookroom-phi.vercel.app)**

Проєкт створено як фінальна робота курсу Full Stack розробника (GoIT), а потім доопрацьовувався поза курсом.

## Технології

- **Next.js 15** (App Router) + **React 19** + **TypeScript** (strict) — фронтенд і серверні компоненти
- **MongoDB** + **Mongoose** — база даних
- **Auth.js (next-auth v5)** — авторизація через email/пароль та Google
- **Zod** — валідація тіла запитів на API-рівні (схеми, allow-list для PATCH-ендпоінтів, cross-field правила)
- **CSS Modules** — стилі, повністю адаптивний дизайн (mobile-first: 320 / 768 / 1440)
- **TanStack Query (React Query)** — кешування й синхронізація серверних даних на клієнті
- **Formik + Yup** — форми та валідація на клієнті
- **Cloudinary** — зберігання й оптимізація зображень (обкладинки, аватари)
- **Нова Пошта API** — вибір міста й відділення при оформленні замовлення чи обміну
- **Resend** — email-сповіщення про нові повідомлення, замовлення й пропозиції обміну
- **Vitest + Testing Library** — юніт-тести (бізнес-логіка, API-валідація, авторизаційні хелпери, компоненти)

## Структура проєкту

```
bookroom/
├── src/
│   ├── app/
│   │   ├── page.tsx                    # Головна сторінка
│   │   ├── layout.tsx                  # Кореневий layout з навігацією
│   │   ├── error.tsx / not-found.tsx   # Глобальні сторінки помилки й 404
│   │   ├── catalog/page.tsx            # Каталог книг із фільтрами, пошуком і пагінацією
│   │   ├── book/[id]/page.tsx          # Сторінка книги: опис, рецензії, пропозиція обміну/купівлі
│   │   ├── book/[id]/edit/page.tsx     # Редагування власного оголошення
│   │   ├── users/[id]/page.tsx         # Публічний профіль іншого користувача
│   │   ├── profile/page.tsx            # Профіль: редагування, мої книги, покупки, обміни
│   │   ├── chat/page.tsx               # Чат зі списком розмов, непрочитаними, пропозиціями обміну
│   │   ├── sell/page.tsx               # Форма додавання книги (кілька жанрів, фото, продаж/обмін)
│   │   ├── auth/register, auth/signin  # Реєстрація і вхід (email/пароль + Google)
│   │   └── api/                        # 20 route-файлів: books, users, messages, orders,
│   │                                    # exchanges, comments, reports, novaposhta, auth
│   ├── models/           # User, Book, Comment, Message, Order, Report (Mongoose)
│   ├── lib/              # mongodb, auth, apiAuth/apiValidation/apiSchemas (спільна
│   │                      # авторизація й Zod-валідація для API), novaPoshta, cloudinary, email...
│   ├── components/       # ~40 компонентів, кожен у власній папці з CSS Module і тестом поруч
│   └── types/            # спільні TypeScript-типи
├── package.json
├── next.config.js
└── .env.example
```

## Встановлення

1. Встанови залежності:
   ```bash
   npm install
   ```

2. Скопіюй `.env.example` в `.env.local` і заповни:
   - `MONGODB_URI` — рядок підключення з MongoDB Atlas (безкоштовний кластер підходить)
   - `NEXTAUTH_SECRET` — будь-який випадковий рядок (можна згенерувати: `openssl rand -base64 32`)
   - `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — опційно, з Google Cloud Console
   - `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` / `NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET` — з [Cloudinary](https://cloudinary.com/) (безкоштовного акаунту достатньо), потрібні для завантаження обкладинок і аватарів
   - `NOVA_POSHTA_API_KEY` — опційно, для вибору міста/відділення при оформленні доставки
   - `RESEND_API_KEY` — опційно, для email-сповіщень

3. Запусти проєкт:
   ```bash
   npm run dev
   ```

4. Відкрий [http://localhost:3000](http://localhost:3000)

## Тестування

```bash
npm test          # одноразовий прогін
npm run test:watch
```

Юніт-тести (Vitest) покривають бізнес-логіку без піднятої БД: валідацію (`isValidEmail` тощо), Zod-схеми API-роутів разом із cross-field правилами (ціна для продажу, доставка для обміну, allow-list для PATCH-ів), спільні авторизаційні хелпери (`requireAuth`/`requireSelf` з мокнутою сесією) і окремі компоненти.
